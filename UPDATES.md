# Project Updates

## Summary

This repository is for the More Than A Hack 2027 ball-possession challenge. The task is to generate a frame-by-frame possession file for a full football match and score it against the competition's hidden ground truth using the ranking metric `spellF1`.

The repository's official guidance makes two things clear:

- The main challenge is not per-frame classification; it is temporal possession detection over a noisy tracking stream.
- The public 5-minute ground truth is only for pipeline validation and correctness checks, not for tuning or training.

## Key conclusions from the challenge docs

### 1. Ranking metric is `spellF1`, not per-frame accuracy

The docs explicitly state that the leader board is ranked on `spellF1`, while `macroF1` is reported beside it as a tie-break and a per-frame diagnostic. The reason is important: a model can achieve excellent per-frame accuracy while producing a completely unrealistic number of possessions. The repository emphasizes that possession detection is an interval problem, not a frame-by-frame classification problem.

### 2. The pipeline must be reproducible and fully code-based

The repository states that any submission must be generated by an algorithm. Hand-labelling or human correction of the provided match is prohibited. The same repository must be able to regenerate the exact submission file.

### 3. The public GT is for sanity-checking, not tuning

The public 5-minute GT is provided to validate things like:

- data alignment
- file format consistency
- whether labels meaningfully match a team's possession logic

It is explicitly not a tuning set. Using it to optimize model choices is against the rules.

### 4. The challenge data is noisy and incomplete

The ATD data is automatic and imperfect. The ball is missing for a large percentage of frames, and identity swaps and noisy player tracks are expected. The docs note that handling this noise is a core part of the challenge.

### 5. Smart Tagging is useful as a weak prior

The repository explicitly treats Smart Tagging as a free prior rather than as ground truth. It includes event and phase information that can help identify restarts and team-level phase boundaries, but it is not authoritative and can contain false positives and false negatives.

## Implementation work completed

### Added a stronger solver prototype

I created a new file:

- [starter/possession_solver.py](starter/possession_solver.py)

This solver is intentionally designed to be more state-aware than the repository's baseline. It keeps the provided tracking-based intuition, but adds a more deliberate sequence of steps to improve possession continuity and robustness.

### The solver includes the following logic

1. Team-to-track mapping
   - Reads the ATD metadata XML and maps each track slot to home or away.

2. Ball proximity scoring
   - Uses the nearest tracked player to the ball to estimate likely ownership.
   - Includes a distance threshold and a count of nearby players from each team to reduce noisy flips.

3. Dead-ball handling
   - Treats frames without a visible ball carefully instead of forcing a random guess.
   - Retains previous possession labels across brief ball-loss gaps inside an ongoing possession rather than splitting a valid possession in two.

4. Majority smoothing
   - Applies a centred majority vote over a local time window to suppress flicker.
   - Includes a home-side tie break, matching the challenge's baseline approach.

5. Short-run collapse
   - Merges tiny possession fragments back into a neighbouring label to reduce unrealistic fragmentation.
   - This is important because the ranking metric strongly rewards stable possession intervals over noisy frame-level flicker.

6. Smart Tagging prior integration
   - When available, uses Smart Tagging as a weak prior for restart-related phases and set-piece windows.
   - This is deliberately conservative, because the tagging is not ground truth and should not dominate the actual possession logic.

7. Submission writer
   - Writes the result in the required `frame,label` CSV contract, with `H`, `A`, and `D` codes.

## Why this design was chosen

### It matches the challenge's emphasis on temporal possession structure

The docs repeatedly warn that frame-level accuracy is not the real objective. A submission with a high frame score but a high false possession count can still rank poorly. The design therefore prioritizes:

- stable possession runs
- reduced flicker around transitions
- robustness to missing-ball periods
- preserving contiguous possessions rather than over-splitting them

### It uses a simple algorithm that matches the repo's constraints

The competition allows many methods, but the repository is meant to be reproducible and easy to validate. Using only numpy and the standard library keeps the solver compatible with the challenge scorer and keeps the whole approach transparent.

### It is conservative with Smart Tagging

The tagging is helpful but noisy. The solver uses it only as a weak prior rather than as a replacement for the actual ownership inference. That respects the repository guidance that the provided automated tagging is a strong prior, not a ground-truth answer key.

## Important limitation in this environment

The actual match dataset is not fully available in this sandbox environment. The repository expects the gated challenge data to be downloaded and unpacked into the `data/` directory or pointed to using `MTAH_DATA_DIR`.

Because of that, full end-to-end scoring against the full match or the public ground truth could not be completed here. The solver logic itself was implemented and unit-tested, but final leaderboard-level scoring requires the real match asset bundle.
